What it does, line by line:
  - `normalized` is the HTTP error text (lower-cased somewhere upstream).
  - The branch is a three-way OR of SUBSTRING tests: "payload too large",
    "413", "entity too large".
  - The substring decides WHICH toast sentence the user sees
    (`attachmentsTooLarge`). The sentence is not selected by a status code
    value, not by an error type, not by a class - only by prose that happens
    to be in the response body.

Why it is wrong (the part AC#5 copies):
  - The server may reword: "request entity too large" still hits, but
    "the uploaded file exceeds the maximum size" does not - the toast silently
    never appears.
  - "413" is matched as a DECIMAL SUBSTRING, not as a status code: any body
    containing the digits 413 anywhere (an id, an offset, a model name) fires
    the branch. It is the shape the ticket forbids: "英文错误串里有没有某个
    数字".
  - The ticket's one-line summary ("靠 413 子串决定弹哪句") is a SIMPLIFICATION:
    the real code is a three-substring OR, of which "413" is one. This file
    records the verbatim form so the next reader does not inherit the summary.
