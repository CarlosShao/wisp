### The trade the two shapes expose (this is the finding, not an opinion):
  - Shape A is affordable but MISSES fires() (camelCase filter). Shape B catches
    fires() and the third family member (Complete) for 82% noise.
  - Root cause is not the tokenizer: the CLAIM a comment makes about a name is not
    recoverable from the name. CloseScope is a deliberate historical reference and
    looks exactly like a dangling callable; DEFERRED is a documented marker and looks
    exactly like a call. Any rule separating them is a rule a human wrote, i.e. an
    allowlist - and the fix for a new gate being "maintain an allowlist" is the
    tools/d22scan/allowlist.txt shape, a frozen no-touch path for a leg like me.
  - Cheaper shape that would actually pay (OFFERING, not building): scope the rule to
    a named vocabulary instead of to English. "every token in blacklist.go comments
    matching ^a[A-Z][A-Za-z]*$ must be a func/method of package risk" = 6 names total
    (aEq aUnder aAnyForm aRelates aRuleReason + the defect), FP surface bounded by
    that vocabulary. It catches aEquiv-class drift in THIS file family and costs ~0
    noise. It does NOT catch fires() and it does NOT generalize; and it is still
    contract-adjacent = human approval, so it needs a ticket, not a leg.
  - ? aEquiv had ZERO runtime footprint: my own AC#4 proves it (247/140/1/1 unchanged,
    red-name symdiff 0, RUN-name symdiff 0, on both platforms). That is why no
    existing instrument could have caught it, and why "put it on an instrument" needs
    a NEW dimension rather than widening an existing gate.
  - Two more same-family names found in this package and NOT in my write face,
    reported for a separate ticket: disposalScope + taskScopeID (provenance.go).
