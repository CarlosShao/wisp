5. ★必答（A996）：324-r1 在 255 尺里加严的两处是不是「只加不减」

**成员数地板**＝`config_receipt_255_test.go:275-279`（在 `if len(fields) < 14 { t.Fatalf }` 之后、逐段循环之前）：
`for _, field := range fields { if n := len(configSectionMembers(t, field)); n < 2 { t.Errorf(…) } }`
- 判据形状：一枚**新的** `t.Errorf`，条件是"段成员数 < 2"。它⛔ 与任何既有判定共享变量、⛔ 不改 `got`／`want`、
  ⛔ 早退（用的是 `t.Errorf` 不是 `t.Fatalf`）⇒ 只会**多**红，结构上不可能把一枚红改成不红。
- 反证它"不是装饰"＝读数件 01 的**突变乙**（把 `configSectionMembers` 摘成恒空）⇒ 地板 14 枚逐枚点名红。
  ⚠ 本腿在 HEAD 树量到地板触发次数＝**0**（post／head 两发都 rc=0）＝今天的 schema 满足它，⛔ 等于它没牙。
- 豁免面：地板对 14 枚段**一视同仁**（射程＝`configSectionsForScan()` 的全部），⛔ 按段名点名放行；
  ⛔ 扩大豁免＝`rosterScanSkipFiles` 在 diff 里零改动（读数件 02 的 AC#4 面核）。

**逐枚日志**＝`:283` `sectionLogged := 0`／`:286` `sectionLogged++`／`:293` `t.Logf("SECTION %d/%d …")`：
- 判据形状：`t.Logf` ⛔ 计入 `testing` 的失败判定（Go 仪器事实：只有 `Error*/Fatal*` 会置失败位）；
  `match=%v` 那格调的是与 `:294` 判据**同一个** `slicesEqualSorted(got, want)`＝同形复算，⛔ 新口径。
- 唯一的副作用是**顺序**：`sectionLogged++` 在 `want, ok := sectionReadSites[field]` 之前，
  于是"某段无 site 条目"那一支（`:289` 的 `t.Errorf`＋`continue`）会让计数**比总段数少 1 枚**的假象？
  ⛔ 不会：`continue` 之前已经 `++`，所以打印出的 `i/14` 与真实索引一致（本腿实测两发都是 1/14…14/14 满 14 行）。
- 结论：两处都**只加不减**（本腿的凭据＝§4 的 4 行 `^-` 全名册＋两棵树 14 段逐枚对拉＋3 枚邻居用例同色＋
  地板／日志的形状读码）。**它没有把任何一枚判据从"会红"改成"不红"、⛔ 放宽断言、⛔ 扩大豁免。**
  唯一的**语义变更**是 `readsFieldAccess` 那一支收紧＝一次**有意的、被编排者裁过的**（A996 裁乙′）
  判定收窄，效果＝`got` 少 1 枚文件；它会把"该被算成读者的同名镜像段字段"也算漏（残余，见读数件 02 的探针实测），
  ⇒ 那一维⛔ 属"顺手加严的两处"，本腿单列。
