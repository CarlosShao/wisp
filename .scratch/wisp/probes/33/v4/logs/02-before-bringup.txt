327: 	// PRECONDITION (33-r7): the thread that creates the panel window must have
328: 	// nothing left to dispatch. This is not belt-and-braces wording - it is the one
329: 	// thing four measured shapes agree on. Planting "a live window this thread owns

332: 	// (.scratch/wisp/probes/33/r7/modes-grid.txt, docs/evidence/s1/33-panel-host-c27-r7.md ①):
333: 	//   - remove only WM_QUIT before create (the 33-r6 narrow form, kept below): PANIC 3/3.
334: 	//     The close is dispatched by the create's own pump, the library posts the quit
335: 	//     it generates, and the quit is not yet visible to the filtered peek
336: 	//     (measured: removed=0, filtered found=false, next GetMessageW returns WM_QUIT).
337: 	//   - dispatch the close, then run that same quit drain: PANIC 3/3, same reading.
338: 	//   - purge the WHOLE queue without dispatching (the 33-r6 wide form, 4be1d3f1):
339: 	//     the prior owner's window stays alive (thread windows 3 -> 4, an unbounded
340: 	//     leak per create) and 1 of 3 runs HUNG in Embed's GetMessageW until the test
341: 	//     binary timed out (modes/wide-2.txt). The full-package reading of that form
342: 	//     is on disk too: purge hit its cap at 256 removed and the show never

344: 	//     log, not re-run by 33-r7).
345: 	//   - dispatch until the queue reports empty: create SUCCEEDS 3/3 and the orphan is

351: 	// measured here is a half-initialised controller, which on this box can take the
352: 	// whole process down (rc=139 reading in the evidence file's ①).
353: 	//
354: 	// The shipping topology satisfies the precondition by construction: the resident
355: 	// panel thread (cmd/wisp/panel_resident_windows.go) locks its OS thread for life,
356: 	// creates nothing before the first show, and is destroyed with its windows and its
357: 	// quit when loop returns - it never hands a used thread to anyone. That is also why
358: 	// the drain below stays, and why it is still narrow: an undispatched WM_QUIT with
359: 	// nothing else queued IS removable, 33-r6's nail pins that, and refusing for a
360: 	// latched quit we cannot even see would be a guess.
361: 	//

363: 	// 33-v2 问② asked for by name (.scratch/wisp/probes/33/r9/01-fifth-shape-1.txt,

375: 	// and this check alone cannot tell an orphaned close from a live owner's.
376: 	// Consequence, now written down instead of inferred: any recovery that dispatches

383: 		return fmt.Errorf("%w: this thread still has an undispatched WM_CLOSE queued for hwnd 0x%X. The thread's owner must dispatch its queue to empty - purging without dispatching leaks the prior window and can swallow this create's own completion message", errPanelRefusedThread, closedHwnd)
384: 	}

387: 		Debug:     false,

389: 		AutoFocus: false,
