## ★★这批的特殊风险（⛔ 漏读就坏事）
1. **`procX` 是 `syscall.NewLazyDLL(...).NewProc("X")` 拿到的函数指针。删掉一个未使用的 `procX` 是安全的（它不按内存偏移被读），但它常常和「调用它的那个函数一起死」——先看调用者是不是也死了，别只删一半留下悬空调用。**
2. **⛔ 见 unused 就删**——判据仍是派单四档：
   - ①**ABI 结构体字段** → `//lint:ignore U1000 <点名哪个 API 按偏移读>`
   - ②**故意保留的句柄/资源** → `//lint:ignore U1000 <为什么留>`
   - ③**真无主的 func/var/const** → **删**（删前 `git grep -n '<名>'` 全仓核 + 看调用者 build tag）
   - ④**只在 winlive/其它非默认 tag 下有主的** → **⛔删 ⛔ignore**，证据件点名调用者 `file:line` + tag
   - **本波已带 `-tags=winlive`**，所以④类会**自然消失**（真被 winlive 测试用了就不报了）。若你看到某条在**带 tag 后仍报**，那它不是④类，是①/②/③之一。
3. **ST1003 改名**（若本波出现 `deviceId→deviceID` 之类）：改**声明＋全部引用点（含注释里的引用）**；改名前后 `git grep -c '<旧名>'` 必须归 0；改前先核名册面（`scripts/portable-tests.sh` GUARD、票 171 名册、`tokens_table_test`）。
4. **ST1005/ST1012/ST1021/ST1000 是文风**：真改文字/命名，**⛔ 用 lint:ignore 蒙**（④类除外，但④要求点名调用者）。
