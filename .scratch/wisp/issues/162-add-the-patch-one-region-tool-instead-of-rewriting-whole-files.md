## 这是什么（人话）

今天模型要改一个文件里的一行，只能**把整个文件重新打一遍**交回来。它只要漏抄一段，那段就没了——**而且不会报错，只会安静地少东西**。
"只改这一小块"的工具就是给它一个形状：**交回"旧的那段"和"换成哪段"**，由我们去文件里定位并替换。定位不到就响亮失败，绝不落盘。

## 为什么值得做／不做的后果

不做的后果不是"少个便利"，是**数据损坏没有信号**：整文件写回出错的样子和成功一模一样。这是所有同类产品的第一高频工具，缺它＝每次改动都在赌模型抄得全。

## 我的推荐（**owner 选路，我推荐其一**）

**推荐＝进核心工具表（`D34` 加一枚 `fs.edit`，L1）**，不走插件。理由：① 它是**写文件**这一族，和 `fs.write`/`fs.trash` 共用同一套路径解析与门控（`RiskAssessor`＋`PathResolver`），做成插件就得给插件开一条写出口 ⇒ 等于把权限层打个洞；② 我们的 `C26` 路径解析、`R8` 风险判定都按"内置工具"设计，插件那一层拿不到这些前提。
**不按推荐来的坏处**：走插件＝要么削弱路径解析（`AGENTS §1.2` 明令不许在 `PathResolver` 之外做文件系统决策），要么给插件单开特权面（那是新增契约，比加一枚工具贵得多）。

## 判据形状：照 Pi 那四条拒绝抄，但**别抄它的写入**（我逐条读过原文，`packages/agent/src/harness/tools/edit-diff.ts`）

1. 定位＝**字面子串**（不是行号、不是差异格式）：`content.indexOf(oldText)` 精确优先（`:205`），失败再走**一层** Unicode 修复（NFKC／逐行去尾空白／弯引号破折号→ASCII）。
2. 匹不上＝**响亮报错且绝不落盘**（`:261` 文案逐字："must match exactly including all whitespace and newlines"）。
3. 匹上多处＝**另一种硬错**，且**先数一遍再拒**（`:248` `countOccurrences`／`:330` `>1`），**报错文案直接写补救动作**（"provide more context to make it unique"）。
4. 空的拒（`:278`）；**重叠／无变化整批拒**＝全有或全无（它的测试 `tools.test.ts:430-475` 各钉一发）。
5. 换行与 BOM：**先剥 BOM、按首次出现判定行尾、内部统一成 LF（旧文本与新文本同一把尺）、写完还原**（`:243`／`:307`）。
6. ⚠ **不许照抄的那半**：它的写入调用点是**整文件交出去写**（`tools/edit.ts:127`）。我们 `PLAN.md:1176` 早写了必须临时文件＋原子改名 ⇒ **这一格我们比它严，别因为"上游那样做"就回撤**。
