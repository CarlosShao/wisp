## 这是什么（人话）

L1 是"可逆写入"那一档（新建文件、存草稿、播放媒体）。契约给它的不是一条日志，是**一枚 2–3 秒的执行前阻止窗口，人说"停"就取消**（`PLAN.md:128` 逐字）。
CLI 腿（`wisp run`，也就是**今天唯一真能跑 agent 的那条路**，台账 `A308`）今天是这样接的：

- `cmd/wisp/run.go:357` 传进去的是 **`approval.NewChannels()`——一枚空的通道集合**；
- `internal/agent/approval/gate.go:106-109` 那句"`Channels` 为 nil 就用默认集"**因此永远不会触发**；
- 而 `gate.go:213-216` 自己的注释写着：窗口**未被反对就结束＝执行**（`AnswerTimeout`，且**下一行明写"which the bridge routes to allow"**）——这正是 D4 的意思，代码没错；
- 普查程在生产路径上量到：**`Native()`／`Panel()`／`Veto()`／`DecideFrom*()`／`SetLoaded()`／`Replay()` 各 0 枚生产调用者**。

⇒ 合起来的形状是：**问话会打印（`consoleApprovalUI` 在 `run.go:355` 接好了），但没有任何一条线能把"停"送回去**。那枚 2–3 秒窗口在 CLI 腿上**结构上必然无人否决**——每一发 L1 都是"提示一下，然后照做"。
⇒ 更该在意的一点：**它训练使用者去忽略那句问话**。一枚永远不改变结果的提示，比没有提示更危险，因为它把"我看过了"写进了使用者的习惯里。

⚠ **一句要给代码的公道话**：`run.go:353` 那行注释自己写着"Channels loaded here are the honest set for a console run: no floating ball, no global Esc hook"——**这不是一处被忽略的漏洞，是一处被写明过的取舍**：球、Esc、语音、面板那四枚否决通道全是 GUI 侧的，命令行本来就没有。
⇒ 所以这一票要问的**不是"这里写错了没"**，而是"**命令行该不该有一个自己的否决通道**"。这是口径，不是我该拍的。

## 三个候选，与我的推荐

- **甲（推荐）＝给 CLI 一条它自己有的否决通道，但只在它是"人在用"的时候。** 形状：stdin 是 TTY ⇒ L1 窗口内**真的等一个显式答案**（默认动作从"执行"翻成"问完再动"），L2 沿用强确认；stdin **不是** TTY（管道、脚本、CI）⇒ 自动放行 ＋ **在结果里印一行响的**"非交互模式，L1 已自动放行 N 枚"。
  **为什么推荐它**：这正好是命令行世界对"要不要弹确认"的标准答案，且**零新增档位**（不动 R20 那三档，不动模型）；它把"提示"从装饰变回有意义的一步，同时**不堵住 owner 现在的联调方式**（脚本与 CI 那条支路照样一路放行，只是放行要说出口）。
  **不按推荐来的坏处**：翻默认动作要碰**门的调用方**，如果连"窗口内能否接收答案"这层都要动，很可能落到 `internal/agent/approval/**`＝**冻结面** ⇒ 那一半要人工批准；而且 2–3 秒这个数**本来就是为"人来不及打字"设计的**，所以甲在 TTY 支路上等于把窗口拉长成"等人答完"，这是**行为变更**，不是补根线那么简单（这一点我不粉饰：甲最贵）。
- **乙＝把 CLI 腿正式定义为"无否决通道"，并把那枚窗口关掉。** 不再印那句做不到的问话，改成一行审计日志"非交互，L1 直通"。
  **便宜、诚实、零风险**，但代价是**明写放弃 D4 在 CLI 腿上的那一半**。如果 owner 认为 CLI 只是开发工具、真正的用户路径永远是带球的桌面腿，乙比我写完的甲更对。
- **丙＝什么都不做**（今天的状态）。**不推荐**：它是最坏的形状——**提示存在、否决不存在**，而且它已经在 `run.go:353` 被写成"honest set"，下一位读代码的人会以为这块已经交代清楚了，于是**不再回头看**。这块"看起来已经交代过"的状态正是本仓最擅长骗人的那一形。
