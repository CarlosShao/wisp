## 这是什么（人话）

"内置浏览器"有两种完全不同的东西，先分清楚再决定做哪个：
- **A：让助手能上网逛**（点按钮、读页面）——这是**自动化**，可以外部、可以关。
- **B：在你窗口里显示一个网页**——我们**已经有引擎了**（面板本身就是 WebView2），所以 B 的边际成本极低。
⇒ 本票的推荐是：**A 做成可关的插件；B 只在宿主里留一个受控的第二视图，不许插件自己塞页面进来。**

## 为什么值得做／不做的后果

不做 A：`web.fetch` 那条今天就有（**但结果永不以 HTML 渲染**，是契约明写的），所以**读静态页够用**；缺的是"要登录、要点按钮、JS 重"的那一类，今天完全做不到。
不做 B 的隔离：如果让插件自己往窗口塞视图，就等于**给插件开一条绕过 `C17` 白名单的路**——而那张白名单**还没定案**。这是本票最贵的一条风险，不是性能问题。

## 两件必须先立（先立规矩，再谈实现）

1. **逛到的页面内容必须打"外部内容"标记**，和抓取那条**用同一枚标记**。三家在这件事上不一致（dsh 抓的有、逛的没有），**别照它的漏抄**。
2. **一次浏览的会话/缓存不许跨任务常驻**：要么每次干净、要么明确归口到任务作用域（与票 160 那个句柄形状同族）。⚠ 顺手一条**别抄**：dsh 的抓取里"markdown 中的远程图片照样加载"，那是隐私漏口。
