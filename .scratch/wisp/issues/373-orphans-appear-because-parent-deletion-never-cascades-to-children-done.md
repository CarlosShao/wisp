## 这是什么（人话）

★**`task_log` 是父、`tool_call` 是子**（`ddlV1` 的 `task_id TEXT NOT NULL REFERENCES task_log(id)`）。

★★**而本仓**删父的那几处，都不删子**：

| 路径 | 位置 | 干了什么 |
|---|---|---|
| ★**用户点「清空任务日志」** | `privacy.go:177` → `dao_tasklog.go:134 DELETE FROM task_log` | ★**只删父** |
| ★**`DeleteTaskLog`** | `dao_tasklog.go` | ★**只删父** |
| ★**retention** | `retention.go:197` | ★**只删「时间戳非 NULL」的子** |

⇒ ★★**所以"孤儿"这个类**只有一个总根**：**删父 ⛔ 级联删子**。

## ★★为什么这一票比前面三张都值

- ★**票 366** 只**记录**孤儿（基线化、⛔ 拒开库）⇒ **不减少孤儿**
- ★**票 368** 让**新**行不再永生（DAO 兜底）⇒ ★**但已存在的孤儿仍在**

## ★★主流怎么做（这一条决定形）

- ★**SQL 标准**：`FOREIGN KEY … ON DELETE CASCADE`
- ★★★**但本仓 `foreign_keys` 是关的**（`open.go` 的 `dsn()` 四枚 pragma 里没有它）⇒ **`ON DELETE CASCADE` 今天是死条款**
- ⇒ ★★**两条路**：
  - ★〔甲〕**在 DAO 层显式同删**（`DELETE FROM tool_call WHERE task_id IN (…)` 紧挨父删）⇒ ★**不依赖 FK、立刻有效**
