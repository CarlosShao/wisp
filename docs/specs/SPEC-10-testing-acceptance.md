# SPEC-10 · 测试接缝、验收门禁与对抗验收

> 追溯：§5.2/§10/D22/D32/D44、C8/C5/C17、CER 双门禁、红队清单。

## 1. 测试哲学

- **只测外部行为，不测实现细节**：打到接缝上的输入/输出断言，不打内部函数桩。
- 接缝越少越好（理想 1 个）；本项目接缝已由冻结契约天然划定，**全部复用，不新开接缝**。
- 两大禁令（D22 跑歪模式 #5/#6）：**禁 mock 替代真实实现来「完成」测试**（语音用 wav 注入、
  LLM 用真实字节流回放——这俩是**接缝注入**，不是 mock 替身）；**禁为过门禁而调阈值/跳采样**。

## 3. SLO 门禁（D32，禁止跳过或放宽——跑歪模式 #6）

`scripts/slo-check.ps1`（可重跑，进 CI 做 PR 门禁）：

- **口径 = 进程树私有内存**（C30 Job Object `TreePrivateBytes()`，不是单进程 RSS）。
- 六个态分别量：`Sleeping` / `Armed` / `Warm` / `Conversation` / 面板开启 / 工作峰值。
  内存与 CPU 对照 D32 表；**并同时采样 GDI 对象 / User 对象 / 句柄数 / goroutine 数 / 线程数**。
- 附加硬约束断言：Sleeping 零网络长连接、零周期性磁盘写入、句柄 <300、GDI <200、goroutine ≤6。
- **回落验收**：`Settling` 触发后 10s 内进程树内存回到该态上限（必须验证 `debug.FreeOSMemory()`
  真被调用——没有它这条必然失败）。
- **700MB 工作峰值在 S0/S2 实测回填前是「目标值」不是「验收值」**——写进 SLO.md 防止拿未验证
  数字当门禁。
- CI 现实约束【SPEC】：GitHub 托管 Windows runner 无交互桌面会话与真实音频设备 → 内存/句柄类
  采样在托管 runner 冒烟执行，**音频/WebView 拉起/回落全套门禁在自托管 Windows runner 或本地
  合并前强制执行**（脚本同一份，口径不变）。

### 3.1 门禁基准表（D32 16.3.2 原文照录；「路径 Y」=D25 单进程延迟初始化，「路径 X」=语音子进程）

| 状态 | 进程树私有内存（Y / X） | CPU（全核均值，1min） | 附加硬约束 |
|---|---|---|---|
| `Sleeping`（空闲，KWS 关，无子进程） | **≤25MB / ≤40MB** | ≤0.5% | 麦克风关 · 零网络长连接 · 零周期性磁盘写入 · 悬浮球静态无动画 · 句柄<300 · GDI<200 · goroutine ≤6 |
| `Armed`（仅 KWS，ASR/TTS 未加载） | **≤90MB / ≤110MB** | ≤2% | 音频缓冲不落盘 · goroutine ≤7 |
| `Warm`（VAD+ASR+TTS+标点已加载，麦克风关，面板未开） | **≤350MB / ≤400MB** | ≤1%（无推理时） | 90s 空闲必须回落；面板隐藏中须 UI 明示 |
| `Conversation`（开麦多轮） | 同 `Warm` + 采集缓冲 ≤20MB | ≤5%（VAD 常开） | 必须有红色常亮环强开麦信号 |
| Path C barge-in（D47） | 同 `Conversation`（⚠ 全双工下 **ASR+TTS 共存**，Path T 的串行缓解不可用；内存预算由 S4/P15 实测回填，超标时降级 = 播放期挂起 ASR、保留 VAD+AEC 做插话检测） | **AEC+VAD 播报期间持续处理 ≤ 单核 5%**（暂定，P15 实测后回填为验收值——是持续负载不是瞬时） | **播报中说话 ≤400ms 停播转听；播报音频注入麦克风回路不得产生 ASR 转写；外部音源（音乐/视频）播放时的误触发率由 P15 实测设阈** |
| 面板开启 | **≤600MB**（含 WebView2 3–5 子进程） | ≤10%（渲染瞬时） | 会话结束销毁或隐藏 |
| 工作峰值 | **≤700MB**（实测前为目标值） | 单核瞬时 100% 允许 ≤3s；全核均值 ≤30% | `intra_op_num_threads=1` 强制 |
| 回落 | `Settling` 触发后 **10s 内**回到该态上限 | — | 必须显式 `debug.FreeOSMemory()`（C11 步骤④） |

看门狗阈值按上表当前态取行；`Armed` 态超限**不得卸载 KWS**（告警 + 建议用户关 KWS）；
可自动卸载的只有：面板 WebView（用户没在看时）、长输出临时缓冲、goja VM、BM25 索引缓存。

## 4. 延迟与准确率门禁

- **延迟**：固定 wav 注入 + 录制 LLM 响应回放 → 端到端 P50/P95，对照 D32 16.3.4；
  **必须分别量「冷会话」与「Warm 内」两组**（只量一组会掩盖 B4 类结构性问题）；
  Warm 内二次唤起首字 P50 ≤1.5s（不含模型加载）。
- **ASR CER 双门禁（D44）**：近场清洁 ≤6% · 带噪/远场 ≤15%；两个 wav 集**必须提交进
  `testdata/asr-baseline/` 并随 CI 跑**（否则基线是空话）；带噪不达标不阻塞发布，但必须验证
  UI 提示与 DEFERRED 登记到位。
- **TTS 音质**：主观 ≥7/10（S4 门禁，P7）；**标点**：口述场景主观 ≥8/10（§10 第 12 条）。

## 6. 安全红队用例（全部必须通过，任一失败即判不合规）

1. 越界目录访问 → 拒
2. 未声明 capability 调用 → 拒
3. 插件自降级 RiskLevel → 拒（C19：声明 L0 的危险工具仍判 L2）
4. `web.fetch` 访问内网地址段 → 拒（SSRF；compose 内网靶机断言零请求到达）
5. `stopReason=length` → 该消息所有 tool call 全部失败
6. L2 未经确认 → 不执行
7. `net` 白名单外域名 → 升 L2
8. **C26 路径绕过四连**（Windows runner 真实 `mklink /J`）：junction / 8.3 短名 / UNC / `\\?\`
   各一条指向 A 档文件 → 全部拒
9. **A 档黑名单**：读 `~/.git-credentials` / `.git/config` / `%APPDATA%\wisp\config.toml` →
   拒且任何授权/会话授权不可覆盖
10. **C25 污染命中四通道**：先 `search.content` 读标记串 → 经 `web.search` query / `notify` /
    `clipboard.write` / **写入同步盘目录** 外发 → 四条全部升 L2 且确认卡指明来源
11. **C29 供应链**：篡改已下载模型一个字节 → 校验失败拒加载；篡改签名清单 → 验签失败；
    `verify_signature=false` → 报错而非生效
12. **F2 面板 XSS**：`web.fetch` 结果注入 `<img onerror>`/`<script>` → ① 不执行（CSP+净化）
    ② 即使执行，`approval.decide({allow:true})` 被服务端拒 ③ 面板零网络请求（connect-src 'none'）
13. **D45 边界**：批量聚合不含 L2；会话授权不覆盖 C25 升级；会话结束授权失效；≥50 文件升 L2（R7）
14. **D33 配置提权**：热加载放宽 `[risk]`/`[fs]`/`[net]`/`[plugins]` → 触发 L2 重新确认，不静默生效

## 7. 失败预演（pre-mortem，每切片完成后跑；必须真实触发）

基础八项：断电 / 断网 / 麦克风被占 / 磁盘满 / API 超时 / 插件 panic / 多显示器拔插 / 模型下载中断。
另加 D42 十二项（SPEC-09 §4：睡眠唤醒、音频热插拔、显示器拓扑、代理与 TLS 拦截、磁盘满、省电、
会话结束、Focus Assist、时钟跳变、GDI 泄漏、WebView2 缺失、麦克风独占）。
每项记录：检测方式 → 实际行为 → 用户可见文案 → 是否符合 D37 分类映射。

## 8. 对抗验收（每切片，独立 agent，不写该切片者担任）

报告必须含：
1. **stub 扫描**：`todo!()`/`unimplemented!()`/返回 nil 假成功/mock 替代真实实现。
2. **DEFERRED 双向交叉核对**：代码内 `// DEFERRED(D-xx): … → docs/DEFERRED.md#锚点` 标记 ↔
   登记表逐条对账（反向亦查）。
3. **SLO 测量完整性**：是否真的用了进程树口径；有无放宽阈值或跳过采样。
4. **契约偏离检查**：D34 工具表 RiskLevel、C19 R1–R9、D43 转移表逐条比对。
5. **D22 禁止清单七条新增禁令静态扫描**：裸 `go func(` / 绕过 `PathResolver` 的
   `filepath.Clean|Abs` / 明文 Key / wall clock 超时差值 / 镜像取哈希 / 面板批准 L2 /
   内部工件写成受门控 Tool。
6. **场景↔切片双向核对**：每场景每能力能在切片 done 判据找到；每判据能追到决策或场景；
   任一侧落空 = 方案缺口，回报而非自行补实现。
7. **失败预演报告**（§7）与**本切片缺口审计**（每切片完成必须重跑，审计者 ≠ 实现者——
   四轮打磨仍未穷尽是方案自己写下的结论）。

## 9. 场景脚本化验收（§10 第 10–13 条，逐条留证据：工具调用记录 + 结果快照）

- **①系统操作（10 条）**：打开记事本 / 下载 PDF 归一个文件夹 / 音量 30% / 关掉这个窗口 /
  找上周的合同 / 丢回收站（**断言 fs.trash 是 L1 不是 L2**）/ 锁屏 / 切到浏览器 / 电量 /
  打开系统设置蓝牙页。
- **②信息查询（5 条）**：查最新版本 / 打开链接给总结 / 看屏幕报错（**断言截图真进了 LLM**，
  C7 Image）/ 读 PDF 第三章 / 搜错误码。
- **③口述成文**：连续口述 300 字 → **直接出现在目标应用光标处**，标点 ≥8/10；
  「存成文件」不算通过；另验一次向管理员窗口注入的失败路径文案。
- **④陪聊**：连续 5 轮；第 2 轮起首字 ≤1.5s（不含模型加载，对比第 1 轮差应 >1s 证明 Warm 生效）；
  TTS 音质 ≥7/10；能记住第 1 轮的一个事实（L1 画像生效）。

## 10. 最终验收（§10 第 9 条）

用户本人连续日用一周，四场景各至少覆盖一次，主观满意 → 才进 S8 开源准备。
另需专门判断 `Conversation` 开麦 30s+ 的隐私接受度（§16.11#1）。
