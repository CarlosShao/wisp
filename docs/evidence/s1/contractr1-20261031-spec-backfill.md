### 「非放宽」论证（为什么 5%→26% 不是放水）

1. **行内自带的回填规则被履行，不是绕过**。before 格里逐字写着「暂定，P15 实测后回填为验收值」——
   5% 从立行那天起就是占位符，实测本来就是它注定的归宿；59-r1 正是那次实测（PRECHECK P15 rig）。
2. **5% 是错的，不是严的**。59-r1 用产品同源 silero VAD（含两端点状态机、窗口已剔模型加载）实测：
   消参考＋对齐链 ≈0.00% 单核、VAD 单遍 ≈26% 单核、两遍 53.1%。干 Path C 必须干的活（常开 VAD 做插话检测）
   物理上就要 ≈26% 单核——把门设在 5% 意味着**任何诚实实现都过不了这格**：这不是「门严」，
   是「门错」。错误的门要么逼着实现方造假读数、要么让门沦为废纸，两者都比诚实的数更伤验收。
3. **本次没有立任何新上限**。after 只陈述实测事实并作废不被支持的占位数；「AEC 引擎并入后的
   持续处理验收终值待真 AEC 引擎集成后回填」——终值（含真 AEC 引擎 CPU 的总账）明确仍开口，
   留给票 13/aec3-r1 集成后的实测。⛔ 没有写成「上限调到 26%」：那才叫放宽验收，是另一件事、未经批准。
4. **射程死窄**。其它预算行（≤0.5%/≤2%/≤1%/≤5% Conversation/≤10%/700MB 等）一字未动；
   阈值语义零改动，改的只是把一个被实测证伪的暂定占位数换成带出处的实测数。
