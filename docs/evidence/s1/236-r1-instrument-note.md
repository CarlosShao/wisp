## sec 1 这把尺要回答的问题

**不是**"CI 绿了没有"，也不是"我这一发 rc 是 0 吗"。

是这一句：**在我动手之前就红着的那批具名用例里，有没有任何一枚，是我动手之后才变红的？**

- **具名**：判据是**用例名**，不是枚数、不是包名、不是 rc。枚数相同而名不同＝不同结论（本机实测：两发都是"红 1 枚"，名完全不同，见交付件 sec 3）。
- **之前／之后**：两发必须**同一份字节**、**同一台机**、**串行**。任何一项变了，两发不可比。
- **新增**：只有"之前绿、之后红"才算新增。"之前红、之后红"是常红，"之前红、之后绿"是修好了。

## sec 2 两发：怎么跑

### 发一 — 整包名册红（**只用来取"哪些名字红了"**）

```
unset GOTMPDIR TMPDIR TEMP TMP; export GOFLAGS=
PATH="$PWD/third_party/sherpa-onnx:$PWD/build:$PATH"
go test -count=1 -v -timeout 30m ./<包> > <日志>
```
- `-v` **不可省**：不给 `-v` 就没有 `--- FAIL: <名>` 这一行，名册根本不存在。
- `-count=1` **不可省**：否则 `(cached)` 会让你拿上一次的判决当这一次的。
- `-timeout 30m` 是本仓对重包的硬规矩（`cmd/wisp` 实测整包 344–379 s）。
- 一次只跑一发（起跑时 `go` 进程 0）。**并发跑两发＝两发都不可记账**（`A1124` 同族老坑）。

### 发二 — 单包隔离复量（**只对发一里红了的名字跑**）

```
go test -count=1 -v -timeout 30m -run '^(名1|名2|名3)$' ./<包>
```
- `-run` 用 `^(...)$` **锚定全名**。不锚定会连带跑进前缀相同的别的用例，读数就不是"这一枚"的读数。
- 名字从发一的 `--- FAIL: <名>` **原样抄**，不缩写（本仓有过"按缩写 grep 0 命中"的先例）。
- 至少 **3 发**。1 红 2 绿本身就是计时红的样子；3 发全绿也只能说"隔离下今天绿"（见 sec 8(b)）。

## sec 3 看什么：三种判决，只有一种记账

**判据是发二的 rc 与名，不是发一的秒数。**

| 发二读数 | 判决 | 记账 |
|---|---|---|
| `rc=0` 且 `--- PASS` | **计时红**（争用／负载／窗口） | **不记账**：不进"新增红"，也不许被写进"我修好的红" |
| `rc=1` 且同一名字 `--- FAIL` | **真红** | **记账**：写进红名册，归因到具体一行 |
| `rc=1` 但红的是**别的名字** | **换位**（发一那枚其实绿了） | **记账**，且单独报：它说明两发之间字节或负载变了 |

NOTE **`rc=1` 而红名不是你以为的那一枚**，最容易被吞掉。`go test` 的 rc 是**包级**的，包里有任何一枚红它就 1。**永远读名字，不读 rc。**

NOTE **整包 rc 在重包上今天不可当判据**：`cmd/wisp` 整包本机一发 `rc=1` 而**红名册是空的**（`RUN(top)=162 / PASS=161 / FAIL=0 / SKIP=0`，见交付件 sec 3 的 shot C）。rc 记的是"这个进程没走完"，不是"哪一枚红了"。

## sec 4 什么算"这份日志根本不是读数"：两个恒等式

### 恒等式一（逐包）：**分层的** RUN↔判决对账

```
RUN_top  = grep -cE '^=== RUN[[:space:]]+[^/]+$'     # 顶层起点（不含子测试）
VERD_top = grep -cE '^--- (PASS|FAIL|SKIP):'         # 顶层判决（行首锚定）
RUN_top - VERD_top = 0
```

**[X] 不许用 `grep -c '^=== RUN'` 减 `grep -c '^--- PASS'`。** 这两个数**不在同一层**：

- Go 的子测试起点 `=== RUN   TestX/sub` **也在行首**，被 `^=== RUN` 数进去；
- 子测试判决 `    --- PASS: TestX/sub` **是缩进的**，`^--- PASS` 数不到。

本机实测（`cmd/wisp` 整包，`53b9be53`）：`^=== RUN`＝**220**、`^--- PASS`＝**161**，差 **59**。按层拆开：

| 层 | RUN | 判决 | 差 |
|---|---|---|---|
| 顶层 | **162** | **161** | **1** |
| 子测试 | **58** | **58** | 0 |

=> 那个 59 里，**58 是"层不同"造成的假差、1 才是真的没判决**。拿 59 当"59 枚没判决"是**读错层**；拿它当"没事"则会把那 1 枚吞掉。**两种错都发生过**（本件第一版就是前一种，见 sec 8(e)）。

=> 所以 `scripts/portable-tests.sh:851-856` 打的那四个数**内部不在同一层**（`^=== RUN` 含子测试起点，`^--- PASS/FAIL/SKIP` 只含顶层）=> **`four numbers` 不能直接相减**，也不能当"名级总数"。它只能当**四个各自独立的计数**读，且必须声明层级。

### 恒等式二（逐包）：**声明数 vs 起点数**

```
DECLARED = go test -list '.*' ./<包> | grep -c '^Test'   # 本仓今天 cmd/wisp = 350
STARTED  = RUN_top
DECLARED - STARTED = 未跑到的顶层用例数
```

本机实测（`cmd/wisp` 整包三发）：`DECLARED=350`，`STARTED`＝**162 / 167 / 162** => **183–188 枚整发没跑到**（**52–54%**）。

=> 这条比恒等式一重要得多：**恒等式一只能抓"起了没判"，抓不到"根本没起"**。而"没起"的用例在名册里**一声不响**——它们既不红也不绿，**只是不在**。

### 恒等式三（跨 tier）：四个 tier 的数**不许相加**

`portable-tests.sh` 的 tier 名册（`:244-291` 的 `core_pin`／`win_pin`／`cli_pin`／`winsec_pin`）**互相重叠**，现跑去重：

| tier | 包数 | 与 core 重叠 |
|---|---|---|
| core | 27 | — |
| windows | 11 | **11**（全部在 core 里） |
| cli | 1 | 0 |
| winsec | 1 | **1**（`internal/winsec` 已在 core 里） |
| **相加** | **40** | **去重并集＝28** |

=> 四个 tier 的 FAIL 相加，只在"同一枚用例最多出现在一个 tier 的日志里"时才等于名级总数。**今天不成立。**要用相加，必须先声明"本次相加的 tier 集合互斥"，并给出**包级去重后的并集**；给不出就**不许相加**。

## sec 5 两个口径：名级 23 NOT 包级 3

这两个数**量的不是一件事**，任何一句"23"或"3"都必须带口径：

- **包级 3**＝`grep -cP '^FAIL\t'` => **有几个包的判决是 FAIL**。一个包里 100 枚红也只算 **1**。
- **名级 23**＝`grep -cE '^[[:space:]]*--- FAIL'` => **有几枚用例红了**（含缩进子测试）。一个包红 23 枚就是 **23**。
- => **两者没有换算关系。**"3 个包红"完全可能是 23 枚红，也完全可能是 1 枚红。**拿包级数去证名级结论＝换了口径还声称同一个结论。**

NOTE **口径声明必写三样**：(1)**跑范围**（本机包集 vs CI 全 job）；(2)**层级**（顶层 vs 含缩进子测试）；(3)**tier 集合**（哪几个 tier、是否互斥）。三样缺一，这个数就不可比。

本仓真撞过：`236-a1/census.md:141` 现读——本机基线 `roster-baseline-f7478d37.txt` **17 枚**、CI 那晚 **25 枚**，差 8 枚**不是新增红**，是**跑范围不同**；而编排者早先记的 **11 枚**是用 `gh run view --log-failed | grep -oE` 抽的，**真数 23**。

## sec 6 步名归属：给不出步名时怎么办

`gh run view --log-failed` 抽名册**会漏计**，且**部分 run 的步名列整列是 `UNKNOWN STEP`**（`236-a1/census.md:142` 现读：`run-36556778053`／`run-36500353477` 是 `UNKNOWN STEP`，`run-36559498617` 同发却给得出）。

=> 规矩：
1. 先 `gh api repos/<owner>/<repo>/actions/jobs/<job_id> --jq '.steps[]'` 取**步级名册**（给得出步名与 conclusion）。
2. 给不出步名时，**用正文自报行认步**：`runtests.sh: OK - packages=…`／`portable-tests.sh: four numbers …`／`portable-tests.sh: census GOOS=…`。
3. **[X] 不许把 `--log-failed` 抽出来的名册直接当名级总数**——它是**过滤后**的字节，不是全量日志。

## sec 7 *整包这把尺在重包上会**整族**漏（`A1124(5)`）

**这条不写进来，本说明自己就会漏族。**

- 现象（本机现跑，`cmd/wisp`，`53b9be53`）：整包 `-v` 的 `=== RUN` 跑到 `TestAC13…`／`TestPanelThread…` 一族就停了，之后**整族 `RUN=0`**：
  `TestSLO`＝0、`TestSecret`＝0、`TestResident`＝0、`TestTask`＝0、`TestSubagent`＝0、`TestPlan`＝0、`TestRestart`＝0、`TestProviders`＝0、`TestTempdir`＝0、`TestTicket224`＝0、`TestZZ315`＝0。
- 对照 `go test -list '.*' ./cmd/wisp`＝**350** 枚顶层，整包一发只起 **162–167** 枚 => **183–188 枚整发没跑到**。
- 根因：**Go 按文件名字母序**跑，进程在截断点之前那族里被**截断**（`A1100` 那族的进程级截断）。`cmd/wisp` 里截断点落在 `panel_*`／`plan_*` 附近 => **`plan_*` 之后的族恒 `RUN=0`**；`A1124(5)` 在整仓层面记的是 `panel_*` 之后（`slo_*`／`session*`／`tools*`／`winsec*`…）。
- => **规矩**：任何"整包"读数，**先问一句"这一族排在截断点之前还是之后"**。
  - 排在**之后**的族：**整包的绿对它恒无信息**（不是"通过"，是"没跑"）。
  - 要用它们的读数 => **只能用显式 `-run` 选择器另取一发**。
  - 报告必须写清：这一发**跑到哪儿为止**（最后一枚 `=== RUN` 的名字），以及**因此哪些族没有读数**。

## sec 8 反向判据：本件在哪种情形下会失效

本件是**文档，不是可执行的东西**（派单：文档形的反向判据＝指出它会在哪种情形下失效并给那情形的读数）。四个失效面，逐条给读数：

**(a) 发一截断时，本件会给出"完整名册"的错觉。**
- 读数：`cmd/wisp` 整包三发 `RUN(top)`＝**162／167／162**、`VERD_top`＝**161／166／161** => 每发**恰 1 枚**起了没判（`TestAC13BringUpSurvivesAReusedThreadQuit`／`TestPanelThreadIsSTAAndExitsCleanly`／同前者），**且三发的红名册逐发不同**（`TestPanelHostRealWindowHopAndLifecycle`＋`TestPanelHostLatencyPercentilesAC2` ⇄ `TestAC14GoSideEvalPushReachesThePage` ⇄ **空**）。
- => 靠 sec 4 恒等式一挡：`RUN_top - VERD_top != 0` => 这一发**不许当名册**，换小包或换 `-run` 重取。

**(b) 发二只跑一发就判"计时红"。**
- 读数：`TestTicket223RefusedLooseningKeepsOldValues` 隔离 **5 发全绿**（7.24／7.62／8.31／7.44／7.70 s），而它在整包三发里**也是绿**（7.33／7.18／7.89 s）=> 这枚**今天压根没红过**，不许被写进"计时红"那一栏凑数。
- => **"发二绿"只证明"隔离下今天绿"**，不证明"发一那枚是计时红"。发一绿＋发二绿 => 它没红过。

**(c) 拿 tier 相加当名级总数。**
- 读数：`core=27 / windows=11 / cli=1 / winsec=1` => 相加 **40**、**去重并集 28**；windows 的 11 个包**全部**已在 core 里，winsec 那 1 个也在 core 里。=> 靠 sec 4 恒等式三挡。

**(d) 本件挡不住"两发之间字节变了"。**
- 本件要求两发同字节，但**没有**任何自动手段在两发之间冻结工作树。本机实测真咬到一次：`cmd/wisp` 在 12:57:28／12:58:20／12:59:27／13:11:15 出现别的腿的四枚 `zz227r1_probe*_test.go`，**正好横跨我的发一与发二**。
- => 规矩：两发都要记 `git rev-parse --short HEAD` ＋"参与编译的文件集指纹"（`*.go` 逐个 sha256）。两次指纹不同 => **两发不可比，重取**。

**(e) 本件自己第一版就踩了 sec 4 那个坑（留档，不抹）。**
- 第一版把恒等式写成 `grep -c '^=== RUN'` 减 `grep -c '^--- PASS'`，于是把 `cmd/wisp` 整包读成"**59 枚没判决**"。按层拆开后真值＝**1 枚**，那 58 是**子测试起点被数进去、子测试判决没被数进去**的层差。
- => 反向判据的具体形状：**任何人把这两个数相减并报出一个非零"未判决数"，都要先问它是哪一层的差。**`^=== RUN` 与 `^--- PASS` 之间今天恒有一个**等于子测试枚数**的假差（本机 `cmd/wisp`＝58）。
