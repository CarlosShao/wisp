## 2. 缺陷①的修法：为什么用"两枚都启用"的树

`145-accept-r1.md` §5.1 的现量指出：仓里两棵"两模型"假树的第二枚恒 `enabled=false`，断言一律 `len==1` ⇒ 测的是**过滤方向**（未启用的不许进），**不是复数方向**（两枚启用的都要在）。所以 `mut-onerow`（只肯给第一枚）全仓零红——那是**真空洞**，不是仪器没接上（同程 `mut-zerorow` 双红已证 overlay 生效）。

`settings145TwoModelBase` 因此是**第一棵两枚都启用的树**：

```toml
[llm.providers.acme]
protocol = "openai-responses"          # 非预设 provider 必须显式给协议（validate.go:214-222）
api_key_ref = "env:ACME_KEY"

[llm.providers.acme.models.first]
enabled = true
context_window = 128000
display = "Acme First"
thinking_levels = ["low", "medium"]

[llm.providers.acme.models.first.capabilities]
thinking = true

[llm.providers.acme.models.second]
enabled = true
context_window = 64000
display = "Acme Second"
thinking_levels = ["low", "high"]

[llm.providers.acme.models.second.capabilities]
thinking = true
```

判据是**逐字**（AC 逐字禁止"字段非空"充当判据）：

```go
wantRows := []ChatModelOption{
    {Provider: "acme", Model: "first", Display: "Acme First"},
    {Provider: "acme", Model: "second", Display: "Acme Second"},
}
if len(opts.Models) != len(wantRows) { t.Fatalf(...) }
for i, want := range wantRows {
    if opts.Models[i] != want { t.Errorf("row %d = %+v, want %+v verbatim from the tree", ...) }
}
```

另外三条同族断言，各钉一个易错点：

1. `CurrentDisplay == "Acme First"` —— 当前模型的显示名走同一趟 walk（不是另一趟）。
2. `ThinkingLevels == "low,medium"` —— 当前条目**自己的**两档，**不是**四值枚举。
3. 遍历 `ThinkingLevels` 断言**没有 `high`** —— `second` 声明的是 `low|high`，若 reader 答错了条目，`high` 会漏进来。

## 3. 缺陷②的修法：两问分开答，交集在 Go 侧算一次

### 3.1 第一问（维在不在）落在 `internal/config/settings_187.go`

```go
func thinkingDimensionDeclared(spec ModelSpec) bool {
    if !spec.Capabilities.Thinking {
        return false
    }
    return len(spec.ThinkingLevels) > 0
}
```

**规则与它的理由（写进代码注释，同一份话在这里）：**

- `Capabilities.Thinking` 是**存在性的权威**。`SPEC-03 §3.1` 让每个能力位默认 `false`、探测优先（"新增模型默认 `capabilities` 全 false ＋ 引导探测"），所以没声明该位的条目**不是"大概能思考"，而是 UNKNOWN**，UNKNOWN 什么都不提供（宁缺毋造）。同一形状已由语音链路承担：缺 `AudioIn`/`AudioOut` 位的元素被直接摘掉（`internal/speech/cloudcatalog.go:95,99`）。
- 非空 `ThinkingLevels` 是条目**自己点名的档位表**。声明了位但没点名档位 ＝ "这一维存在，我不点名任何档" ⇒ 适配器不映射任何档，**空报价是诚实的答案**，不是拿四值枚举去猜。
- **位是否决项（vetoes）**：位为 false 时，声明的档位被**丢弃**，不被信任。这是刻意的——这是让"条目内部矛盾（声明了档位、从未声明能力）"朝"不提供无法论证的请求"那一侧收敛的唯一顺序，也是让**全 false 默认**安全而非意外宽松的原因。

**为什么不是更松的规则**（写成明文，避免下一位再问一遍）：候选规则 (b)"声明了 `thinking_levels` 就当作隐式声明了能力，位只能否决"会让"位从未被问过"这一缺陷在多数真实配置里继续存在——因为 `Capabilities` 全 false 是默认，`ImportDiscovered`（`internal/llm/discover.go:113-121`）导入的条目**一个能力位都没有**。选 (a) 严格位控 ＋ **让夹具显式声明该位**，读方才真的在问那个位。

### 3.2 第二问（有哪几档）落在 `cmd/wisp/run.go`

```go
func intersectThinkingLevels(declared, accepted []string) []string {
    if len(declared) == 0 || len(accepted) == 0 {
        return nil
    }
    out := make([]string, 0, len(declared))
    for _, want := range declared {
        for _, have := range accepted {
            if want == have {
                out = append(out, want)
                break
            }
        }
    }
    return out
}
```

- 顺序＝**模型声明序**（不是适配器序，也不是排序后的序）：读方拿到的就是"该模型自己的档，只保留能发出去的"。
- `"off"` **按构造掉出去**，且这是实测事实不是巧合：配置侧枚举四值含 `"off"`，而每个适配器的映射表都测 `intensity != "" && intensity != "off"`（`openairesponses/request.go:139-143`、`anthropic/request.go:124-129`），所以 `"off"` **从不**是注册的档位词（`llm.RegisterThinkingLevels` 喂的是 `effortLevels` / `thinkingBudgets`）。`"off"` 仍然有意义——它是"不要思考"的请求——但它走 `CurrentThinking`，不走档位表。
- 空结果是**真答案**：模型没点名档位，或适配器一个都不映射（`openai-chat` 注册 `nil`）。两种都让页面不提供档位选择，而不是造出四值枚举。
- **交集在 Go 侧算一次**，理由逐字抄裁定："两个清单并列、让每个页面自己算交集＝把同一个判断散到每个读方；Go 侧算完再送，读方拿到就是能发出去的档"。下一个消费者（CLI、第二个窗口、一枚测试）不必再推一遍，也不会和第一个推出不同的答案。

### 3.3 两条生产泵腿**形状不同，且各自把话说清**

| 腿 | 文件 | 有没有 provider | 送什么 | 读方怎么区分 |
|---|---|---|---|---|
| 流水线腿 | `cmd/wisp/run.go:531` `modelSwitchSection(mgr, chatChainProvider(rt))` | 有（`rt.provs[0]`，`run.go:627` 由 `BuildEndpointProvider` 建） | **交集**（可发出去的集合） | `Adapter != ""` ⇒ 已与适配器核对过 |
| 常驻腿 | `cmd/wisp/panel_resident_pump.go:175` `modelSwitchSectionFromConfig(m)` | 没有（本进程从未建链） | **声明本身**（已过能力位闸，未过适配器词表） | `Adapter == ""` ⇒ 只是声明，未经核对 |

常驻腿的注释本次补上了这段后果，逐字："with no adapter census there is nothing to intersect, so this section carries the model's DECLARATION - already gated on capabilities.thinking by the config side (AC#2b's existence question) but not yet proven against an adapter's mapping table. That is the most this process can know, and Adapter=="" is exactly how a reader tells it apart from the pipeline leg's sendable set. Inventing a protocol word here to fake the intersection would be the one thing this posture forbids."

### 3.4 线上字段的语义重述（`internal/panel/model_switch_187.go`）

`AdapterThinkingLevels` 原先的注释写着"与 `ThinkingLevels` 分开答"，那在方案 B 下会变成谎话。改成：它是**交集所依据的普查**（census），随行是为了让"页面显示空报价"能说清是**哪一半**空的（"模型没点名档位" 与 "适配器一个都不映射" 是两句不同的话）；**它本身不是报价**，报价是 `ThinkingLevels`。
