## 4. 缺口清单

> 每条格式：**理由（大白话）** → **现状证据** → **冻结面冲突判定** → **可派发性** → **票面落点建议**。

### 第一组 · 地基级（不做，后面的安全承诺都打折）

#### GAP-01 「谁在说话」这一层不存在 · 可派发性：`需 owner 拍板`（产品取舍）

**理由**：唤醒词一开，麦克风就常驻在听。而本方案的威胁模型四条主线里
（SPEC-06 §1：中文语音误识别 × 危险工具、插件能力组合、间接提示注入、面板 XSS），
**唯独漏了最物理的那条：房间里另一个人说一句唤醒词就能用你的助手**。
危险动作仍有「原生侧点击才能允许」（D33/F2）挡着，但 **L0 直通这一档是完全不问人的**：
读本地文件、`search.content` 全盘检索、`web.fetch`、`clipboard.read`、`system.get`（含焦点窗口标题）
——SPEC-06 §5 自己把 `sysinfo` 的当前窗口标题列为「高价值泄漏源」。
一个访客/同事/家人站在你电脑前说句话，就能让它把屏幕内容念出来。

**现状证据**：
- 危险级门控见 SPEC-06 §2（L0 直接执行）。
- 「默认闭麦 + 显式开启 + 红色常亮环 + 首次 L2 隐私确认」见 SPEC-00 §2 / SPEC-08 §3 #30
  ——**这套只管「用户自己什么时候开麦」，不管「开了之后谁在用」**。
- KWS 只有唤醒词与**否决词**（SPEC-04 §5），**没有任何说话人判定**。
- 全景调研：**没有任何对标产品解决过这个问题**（它们连常驻麦克风都没有）⇒ 没有现成作业。

**冻结面冲突**：不直接冲突，但会引入新决策（说话人验证的成本 / 首次注册体验 / 误拒率）。
`PLAN §16.11` 未登记此项，属**新识别缺口**。

**票面落点建议**：至少三档，且**第一档成本极低、可以立刻做**——
① 「正在听」的实体信号不可被忽略（当前只有球的视觉态，见 SPEC-08 §2，需实测在浅色壁纸/多屏下的可辨识度）；
② 非唤醒者语境下**降一档权限**（L0 里带隐私的几项改为需确认）；
③ 声纹/本人判定（成本高，需 P 级前置核实，可能应登记为 RESERVED + 触发条件）。

#### GAP-02 做错了只能看着 · 可派发性：`可直接开票`（但需在票面写清与 D4 的边界）

**理由**：整套安全设计的假设是「错的操作在动手前被拦下」。但日常最常见的失败**不是危险操作，
是合法的错操作**：「把下载里的 PDF 挪到桌面」听成「挪到照片」——两步都是 L1、都不危险、
都不拦截，结果就是错的。批量操作更尖锐：D45-1 把 500 个文件合并成一次确认，
owner 看一眼数字点了同意，**方向错了就是 500 个文件白挪**。
现有补救只有两处：`fs.trash`（只覆盖删除这条路）与「审批被拒后一键重放」
（那是「没做」的重放，不是「做错了」的回退）。
**对标产品里这已经是标配**：Claude Code `/rewind`（100 检查点 / 5 种恢复动作）、
Cline 每次工具调用后提交 shadow git、Gemini `/restore`、Roo、Aider `/undo`。

**现状证据**：
- **冻结面（PLAN.md + docs/specs/）里没有任务级回退机制**：grep
  `checkpoint|rewind|undo|快照|回退` 的全部命中都是**不相干语义**——
  SQLite `wal_checkpoint`（SPEC-01 §4.4 / SPEC-02 §2）、WAL `autocheckpoint`（SPEC-09 §4#5）、
  「回退 VS Build Tools」（SPEC-11 §2.1）、「结果快照」（SPEC-10 §9 的留证措辞）、
  以及 SPEC-06 §12 那句 REJECTED 本身。
- **已实现代码侧同样没有**（措辞严谨版：`internal/` 下 `checkpoint|rewind|undo|snapshot`
  有 236 处命中，但**逐族核对后全部属于以下不相干语义**，无一是任务级回退）：
  WAL checkpoint / `autocheckpoint`（`internal/memory/open.go`）·
  面板状态快照 `Snapshot`（`internal/panel/composer.go`，Go→前端的一次性推送）·
  系统进程快照 `SystemProcessSnapshot`（`internal/proc/systemprocs_windows.go`）·
  诊断包里的 `SLOSnapshot` / `ConfigSnapshot`（`internal/observe/diagnostics.go`）·
  taint marks 快照（`internal/risk/provenance.go`）·
  **以及大量「不是 undo」的否定式注释**——`internal/agent/approval/report.go:13`
  「never render a cancelled call as a clean undo」、`internal/tools/fs_write.go:25`
  「a cancel is never rendered as a clean undo」、`internal/agent/approval/window_test.go:18`
  「a block, not an "undo"」。
  ⚠ **这族注释本身就是证据**：仓内已经反复强调「取消 ≠ 回退」，
  正好说明「回退」是一个**被刻意排除、因而从未实现**的能力，不是遗漏的疏忽。
- `PLAN.md:136` 与 SPEC-06 §12 的 REJECTED 条目**只否掉了**「一律不确认 + undo 兜底」。

**⚠ 冻结面冲突判定（最容易写错的一条，务必逐字读）**：
`PLAN.md:136` 原文「排除『一律不确认 + undo 兜底』：shell / 删除 / 外发无法可靠 undo，是假承诺」；
SPEC-06 §12 原文「不做『一律不确认 + undo』」。
⇒ **它否掉的是「用 undo 替换确认门控」，不是「给已发生的合法操作提供回退」。**
本缺口提的是**后者**，与 D4 不冲突。
⇒ 但票面**必须显式声明这条区分**，否则会被对抗验收按「复活 REJECTED 项」判失败。
⇒ 同时必须**如实列出退不了的东西**（`shell.exec`、D46 命令插件的外部副作用、
已发出的 HTTP 请求、同步盘已上传的内容）——这正是 D4 当初否掉「undo 当兜底」的理由，
不许在新功能里把同一句假承诺换个位置再讲一遍。

**票面落点建议**：任务开始前留锚点（仅对授权目录内、经 C26 解析的路径）→ 任务结束后可一键
「撤销本次任务的全部改动」→ 退不了的部分单独列清单。注意与 C20 `PathLock`、
D31 原子改名、`artifacts\` 500MB 配额的关系（快照本身占空间，需计入配额或另立配额）。

#### GAP-03 它不会问你 · 可派发性：`可直接开票`

**理由**：`SPEC-07 §3` 的 D34 权威表列了 30+ 工具，**没有任何一个能让它回头问用户一句话**；
`SPEC-08 §3` 的 20 态转移表里**没有「正在问」这个态**。碰到歧义它只有两条路：
猜了直接干（L1 阻止窗口只有 2–3 秒，用户很可能根本没看屏幕），或者失败。
**语音场景下这是最亏的**——它明明可以出声问「按类型分还是按日期分？」，用户回一个词就完了。
DSH 有 `ask_user_question`、MiniMax 有 `ask_user`、Gemini 有对应的交互工具，
**这是从 CLI 到桌面全品类都有的东西**。

**现状证据**：
- D34 表全文（SPEC-07 §3）无提问类工具。
- 20 态表（SPEC-08 §3）无等待用户回答的状态；最接近的 `AwaitingApproval` 是**审批**语义
  （只处理 L2 允许/拒绝），不是**澄清**语义。
- `PLAN §16.11` 未登记此项。

**冻结面冲突**：加工具=改 D34 权威表；加状态=改 D43 转移表（SPEC-08 §3 明文「未列出的一律非法」）。
⇒ **两者都是契约级变更**，票面必须写明「本票需要一次契约变更批准」，
且**不得自行往 D34/D43 里加行**——按 SPEC-12 §4.1 走人工批准。

**票面落点建议**：工具（如 `ask.user`，L0，超时判「未回答」而非阻塞）+ 状态（或在
`AwaitingApproval` 里区分两种语义，二选一由 owner 定）+ 回答必须能被**一个词**接住
（语音场景下不接受「请输入 Y/N」这种设计）+ 超时行为要与 C18 的 300s 拒绝语义对齐。

#### GAP-04 动手之前不给你看计划 · 可派发性：`需 owner 拍板`

**理由**：用户能看到「它开始动了」「它调了哪个工具」（SPEC-08 §5.4 的工具 chip），
看不到「它打算怎么做」。而计划模式这两年已是标配：Claude Code、Codex read-only、

要用户点头才离开计划模式。**对语音尤其值**：与其事后弹十几个确认，

**现状证据**：

  ① 只报数字不报意图，② 当前是**死代码**（`Aggregate` 对全部在产工具恒返回 nil，

分类器」，计划模式是「任务开始时一次意图陈述 + 用户确认」。票面必须把这个区分写清楚，
否则会被读成「复活 D11」。

**票面落点建议**：优先把 D45-1 从死代码激活（`pending-and-issues.md:482`）并扩出「意图陈述」；

### 第二组 · 安全模型上仍开着的口子

#### GAP-05 插件跑起来之后，它自己的网络出口没人管 · 可派发性：`可直接开票`

**理由**：`net_allowlist` 管的是**我们替它发的**请求（R5 判的是工具调用目标，SPEC-06 §3）。
但 `shell.exec` 与 D46 命令插件起的是**真程序**——`git`/`ffmpeg`/`docker`/`lark-cli`
想去哪就去哪。我们管得住声明，管不住实际行为。
**这正是本仓自己反复抓的「声明 ✓ / 实测 ✗」形状**（见 `pending-and-issues.md` A33、票 11 的
probe 设计）。Codex 的做法值得参考：`workspace-write` 下**默认把网络关掉**，
要用再显式 `network_access=true` 打开。

**现状证据**：
- SPEC-06 §3 R5 只判工具调用参数里的网络目标。
- SPEC-07 §4 的 D46 清单里有 `env_allowlist`（防凭据泄漏给子进程），
  **没有任何网络层约束**——因为子进程的网络无法从宿主侧收口（诚实的技术事实）。
- `91-os-isolation-memo.md` 已记录：降权层唯一能挂的对象就是这些子进程，
  且 R21 决定「OS 级隔离这一期不做」。

**票面落点建议**：二选一，且**都必须诚实**——
① 真去关（需要 OS 级手段，R21 已否，故可能要登记为票 100 的触发门之一）；
② **在插件卡片与文档上明写「它跑起来之后我们管不了它的网络」**（成本极低，符合
   SPEC-04 §6.4「不得给虚假安全感」的既定纪律）。**不许假装 `net_allowlist` 覆盖了它。**

#### GAP-06 记忆写入没有敏感内容过滤 · 可派发性：`可直接开票`

**理由**：L1 画像的提取是「宿主内部动作、不经门控」（D34 注②），而提取出来的内容
**每一轮都全量注入 system prompt**（SPEC-05 §4.1 第 ③ 段，~400 token）**并随请求发给云端模型**。
也就是说：用户随口念的密码、读文件时带出来的敏感串，一旦被提取进画像，
就从「这一次对话」变成「**永久 + 每轮 + 上云**」。
C25 的污染追踪只管「工具调用参数里有没有敏感片段」（SPEC-06 §5），**管不到画像里存了什么**。
MiniMax 专门做了「用户级记忆写入的原因校验，防止项目信息漏进个人记忆」。

**现状证据**：
- SPEC-05 §6：L1 画像「全量注入 system prompt」；提取在 Warm 窗口**异步**跑、不经门控。
- SPEC-06 §5 敏感源列表（`fs.read`/`search.content`/`clipboard.read`/`sysinfo`/
  `web.fetch`/`doc.read`/`screen.capture`）——**打标记的对象是工具输出，不是将要写入画像的文本**。
- A 档黑名单（SPEC-06 §4.1）防的是「读」，**不防「已经读到的东西被写进画像」**。

**票面落点建议**：画像/记忆写入前跑一次与 C25 同源的敏感片段检查 →
命中则**不写入**并在球的反馈里如实说明「这条我没记」；与 D20 的「记住了：X + 一键撤销」反馈合并。

#### GAP-07 权限只有「三档模式」，没有「规则」 · 可派发性：`需 owner 拍板`

**理由**：现有是「每步都问 / 只问高危 / 全自动」三档（票 90，已 done）+ 会过期的会话授权
（D45-2，落 S7）。一次任务内够用，但这是**天天用的常驻助手**——
**每天开机都要对同一个文件夹重新授权**。这跟 D45-1 要解决的「确认轰炸」是同一件事，
只是摊到了几天，而批量聚合这个解药**跨会话不生效**。
对标产品里声明式规则已是标配：Claude Code `Tool(param:value)`（deny 优先于 allow、
跨作用域 deny 胜出、省略参数永不匹配）、OpenCode 通配符 + 后匹配优先、Cline 分类开关、Crush 列表。

**现状证据**：
- 三档模式见票 90（`internal/risk/mode.go`）；会话授权见 SPEC-06 §8.2。
- **跨会话持久授权被登记为 RESERVED**：SPEC-12 §5「跨会话持久授权档（workspace/user）…
  持久授权 × 提示注入风险窗口大」；PLAN §7 同条目。
- 仓内已实测「不存在让会话授权跨重启的路径」（票 90 验收结论，R20/M3 边界）。

**冻结面冲突**：直接撞 SPEC-12 §5 的 RESERVED 条目。**RESERVED = 无实现计划、不得误读为待办**。
⇒ 必须 owner 明确「把这条从 RESERVED 拿出来」，否则 agent 单方面做 = 契约违规。

**给 owner 的取舍陈述**：当初 REJECT 的理由（持久授权 × 提示注入风险窗口大）**成立**；
但代价是每天重复授权。可行的中间形态：**持久授权只对「只读 + 授权目录内」开放**，
写/执行类继续走会话级——是否接受这个折中，需要一句话。

#### GAP-08 可写目录里面没有再分「保护区」 · 可派发性：`可直接开票`

**理由**：C26 与 A/B 黑名单防的是「越界」与「凭据」（SPEC-06 §4/§4.1）。
但「允许写的目录里，有些东西本来就不该被改写」是另一件事：`.git` 整个目录、
构建产物、用户手写的笔记。Codex 在这里专门设了一层「即使在 `workspace-write` 里也递归只读」
的路径（`.git` 含解析 `gitdir:` 指针文件、`.agents`、`.codex`）。
本方案现在的等价物**只有 `config.toml` 一个点**（SPEC-06 §4.1 A 档）。

**现状证据**：A 档列表（SPEC-06 §4.1）共 **9 条**，全是凭据/密钥类

⇒ 一次误判的 `fs.write` 可以静默改坏 `.git/index`（**不可逆**，且不会被 A 档拦下）。

**票面落点建议**：扩 A 档或新设一档「授权目录内的结构保护区」，走 C26 同一入口

需与票 103/108 的密封守卫同批考虑。

#### GAP-09 「停」停不干净 · 可派发性：`可直接开票`（可能已有归属，先查重）

**理由**：控制词「停」确实能取消正在跑的任务——**有实测**
（`control_test.go:76-103` 证明「停」能取消正在跑的任务、`status=cancelled`、`RootPending=0`）。
但取消是**协作式**的：`shell.exec` 与 D46 插件起的是真进程，它不理 `ctx` 就还在跑。
C30 Job Object 保证**进程退出时**连带清理，但「**任务级**立刻杀掉本任务起的全部子进程」
没有明确归属。停止要真的停，停完还要如实说「有一步我没拦住」。

**现状证据**：
- `SPEC-01 §5.3` 已诚实承认「cgo 推理调用不可取消」；路径 X 下「取消 = kill 子进程」。
- SPEC-01 §4.4 的关停顺序第 3 步 = 「取消所有任务 root ctx → 等 WaitGroup ≤3s
  （超时放弃等待并记录未收尾任务）」——**这是进程退出路径，不是单任务取消路径**。
- D37 `cancelled` 错误类的用户可见文案是「静默」（SPEC-01 §5.1）——与「如实说哪几步没拦住」相左。

**票面落点建议**：明确「任务级取消」是否级联 kill 子进程（及与 D46 `exe_hash` 校验、
C18 300s 超时、`user_rejected` 可重放的相互作用）；并把「已产生副作用」的清单
从 SPEC-06 §2 的 L1 取消延伸到**任务级取消**。

### 第三组 · 语音体验（本方案的差异化，更该补）

#### GAP-10 动手之前先让用户看到「我听成了什么」 · 可派发性：`可直接开票`

`RebindHotkeys`（票 07）· `SleepWindowEdgePx`（A29④）· **D45-1 `Aggregate` 对全部在产工具恒返回 nil**
（A20）· 倒计时/队列深度/进度数据源（第 8 次，A33②）· `internal/perm` 零生产 importer（票 101）·
C26 改写账 `RewrittenRoots()` 零生产读者（票 105）· `winsec.SealDir` 零生产调用者（票 132）。
另有「仪器以为在跑其实没跑」一批：`cmd/balldebug -diff` 无论像素计数为何都 `return nil`、
`go test -run <不匹配>` 打印 ok、`d22scan` 的 `frontend/` 作用域走 0 个文件（票 71 立案）。
**这不是个别人的失误，是架构层缺一条不变量。**
DSH 有现成答案：每个包自带 `./invariant` 伴生检查，验证自己那条持久关系还活着，
失败时 `InvariantError` **指名到所属包**。

**现状证据**：以上每条都有票号/台账编号（见上）。
现有对策是**逐票补**（票 71「gates must self-report」），补完还会长出来。

**票面落点建议**：一条**通用仪器**——对「声明的能力入口」做可达性断言
（生产装配根能否走到该符号），失败**指名到包与符号**；与票 121「模型交接链不在二进制里」
的 assembly-reachability 门同族，可合并或复用其做法。
