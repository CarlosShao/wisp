# Wisp 面板前端信息架构（IA）设计 · 2026-10-25

> **作者**：机主直派的架构会话（同一轮 harness 审计的延伸交付）。
> **给谁用**：机主（拍板）＋前端外部 agent（实现）＋编排者（Go 侧接线排程）。按仓规矩（交接件 §3.4），本件由**机主自己**带给前端 agent，编排编队不经手 `frontend/**`。
> **判据**：机主 2026-10-21 铁律——方向一律对齐主流 harness；另受本项目冻结约束（D29 按需面板不常驻、D47 双语音路径、C17 桥白名单、C21 token、**UI 零 emoji**〔d22scan 扫 `frontend/` 全文件、字符串不豁免〕）。
> **现状一句话**（2026-10-25 实测）：前端骨架已是主流形状（Ctrl+K 面板、抽屉侧栏、明暗主题、快照驱动的权限档位条都在），但**活数据面只有三个方法**——`config.get`／`config.set`／`config.models.list`（`internal/panel/bridge.go:72-82`）＋一条出向快照泵；其余屏（会话/任务/审批/终端/文件树）全跑在 `fixtures/` 假数据上。挤牙膏的病根不是前端懒，是**没有一张「页面区块 ↔ Go 接口」的完整地图**——本件就是那张地图。

---

## 1. 设计原则（五条，冲突时按序）

1. **对话流是主页**：主流 harness（Claude Code / Cursor / Cline / ChatGPT 桌面版）进门第一屏都是「当前会话对话流＋输入区」。Wisp 面板同理——语音转写、助手回复、工具调用卡都在这一条流里；**设置不是主页，是对话流右上角的一个齿轮**。
2. **球优先、面板按需**（D29）：面板的每个能力都要回答「为什么这不在球上」——答案是：球管「唤起/正在听/正在想/说完了」四态与红环隐私信号；**一切可读可点的都进面板**。面板会话结束即隐藏（S5 契约），所以 IA 不假设常驻。
3. **左会话、右上下文、中对话**：主流三栏。左＝会话历史（新建/搜索/归档/分叉）；右＝本次任务的上下文（待办/任务/子代理/审批/引用文件），可折叠、窄宽默认收起；中＝对话流＋composer。
4. **一个入口一个词**（Ctrl+K 命令面板）：所有动作可从命令面板直达（主流标配）；设置页只是命令面板里 `settings:` 前缀的另一种皮肤。
5. **C21 token 单一来源＋零 emoji**：所有颜色/间距/字号来自 C21 生成层；界面文案禁 emoji（仪器在 CI 扫，字符串不豁免）。
