# Wisp Harness 改造方案（2026-10-25，规划视角）

> **定位**：本文件是《2026-10-25-harness-deep-audit.md》（下称《审计》）的姊妹篇，回答「接下来怎么改」。视角＝规划/路线图，不是代码细节。
> **原则（对齐机主 2026-10-21 铁律）**：判据＝最有价值＋最符合主流 harness；⛔ 拿「涉契约/风险高/动作大」当降级理由；复杂必须买得到真价值；技术选型 agent 拍并写理由；只有三类摆机主（改契约文字／花钱／不可逆动作）。
> **边界**：本方案不替机主做产品优先级决定（先做语音还是先做面板线是产品问题，只在 §5 给推荐）；改造本身应**立票走本仓既有流程**（编排者派腿、非实现者验收），而不是绕开票制另起炉灶——改造的第一课就是「用被改造的制度执行改造」。
> **未提交声明**：本件与《审计》均未 commit；由机主或编排者按 Git 纪律处置。

## 1. 诊断浓缩与改造总架构

《审计》的结论一句话：**制度设计领先、载体已经过载**。365 张票、6.24MB 只追加台账、日均百笔提交的规模下，「规矩活在文字里、状态活在人脑里、入口活在最新一节里」的三个支柱全部到了极限，表现为四组症状：状态机双信号漂移（69/189 done 票状态行未写 done、20 张活票无状态行）、入口腐烂（停车点 45h 旧、README 依赖图止于票 75、派单存档断档）、决策积压（Q 池约 44 枚无闭口、约 42 张活票等机主一拍）、门禁缺口（CI 现红、零 timeout、git 纪律零强制）。

**改造总架构＝四条主线＋一条底线**：

| 主线 | 一句话 | 对应主流 harness 机制 |
|---|---|---|
| A. 状态机器化 | 票面 schema 封闭化＋校验器＋统计自动生成 | issue tracker 的 schema 校验与看板 |
| B. 知识分层生成 | 台账归档分层＋入口文档由真相源生成 | wiki/release note 的「生成而非手写」 |
| C. 门禁与纪律仪器化 | CI 限时、红即停、本地钩子 | CI timeout + pre-commit/pre-push hook |
| D. 决策通道制度化 | Q 池清点、owner 清单节奏、单点解锁 | weekly triage / decision log |
| 底线 E. 环境治理 | 单盒风险、桌面态死亡区、CRLF 双尺 | hermetic CI、 runner 隔离 |

## 3. 关键设计规格

### 3.1 票面 schema v2（最小改动版）

```markdown
- Status: <ready|in-progress|review|blocked|done|void|reserved>   ← 唯一物理格式；理由括注在行内
- Blocked-By: <票号|Q-NN|owner:一句话>                              ← 等前置/等人时必填
- Last-Update: <YYYY-MM-DD HH:MM +08>
```
- done 仍＝文件名 `-done` ＋全框勾（双信号由 ticket-lint 强制一致）；void＝`-void`；收编＝票尾「收编备注」＋`-void`。
- **不改的**：AC 框、追加式 Progress log、禁改原句、-done 防重领键——这些是被 5 周实证验证过的好设计，全部保留。

### 3.2 `scripts/ticket-lint.sh` 校验器规格（v1 只报、v2 进 CI）

1. -done 票存在行首未勾框 ⇒ 红（正控：附录 A 的 07/92/115 必被点名）；
2. -done 票无任何 `Status:` 行含 done ⇒ 红（现状 69 张，回填后应 0）；
3. 活票无 Status 行 / 词表外取值 ⇒ 红（现状 20 张＋散值）；
4. 双文件同票号 / 票号断档与 voided/ 对照 ⇒ 黄（缺号清单机器对账）；
5. 新票文件名 >100 字符 ⇒ 红（与 check-path-length-budget 的 HAT_NAME_LIMIT 共用阈值，两门合一处定义）；
6. 老化报表：in-progress >72h、review >14d、blocked-on-owner >21d ⇒ 黄清单；
7. 统计输出：done/活/void/等 owner/立即可派（读 Blocked-By 空者）计数——替代手数。
- 自带 `--self-test`：对内置坏样例（临时目录、不碰真票池）逐条验红。

### 3.3 台账分层方案

- 活跃段 `pending-and-issues.md`（近 2 月）＋历史档 `pending-and-issues-YYYY-MM.md`；根文件头 30 行＝机器生成索引：每条 A 一行（编号｜日期｜一句话｜档位）。
- 索引生成脚本从各档 `^## A` 标题抽取，标题本身已含一句话——**零人工摘要成本**。
- 「只追加」纪律语义升级为「各档内部只追加；切档＝整段搬移＋根文件追加一行指路」。

### 3.4 owner 决策清单制度（月度）

- 每月首个汇报附「决策清单批」：≤10 项、每项＝选项/推荐/不答代价/「不做」栏/撤销口令（格式已有机主偏好背书）。
- Q 池闭环标记统一为在 Q 首次登记行追加「→已答（日期/结论/落账 A 号）」——机器可 grep 闭口率。

## 8. 复审补充：对照主流 harness 的二轮发现（2026-10-25 晚）

> 一轮已覆盖的四件（状态机器化／本地钩子／CI 限时／知识生成）不重复。本轮定向复审新验证的事实：README「当前阶段」仍写「尚未开始实现」（实际 5 周 85k 行生产码、189 票 done）；5 周仅 1 枚 tag（`wisp-orch-backup-0927-1057`，编排备份点而非版本里程碑 ⇒ 版本 tag 实际为零）；**dev 分支无任何保护**（`gh api .../branches/dev/protection` 404）；ci.yml `pull_request` 无分支过滤（`ci.yml:9`）、slo-full 跑 `[self-hosted, wisp-slo]`（`ci.yml:1014`）且 D22 mode-6 明令禁 `if:` 门控 ⇒ **PR 事件会在承载开发数据/DPAPI/gh 凭据的那台机器上执行全部 job**（同仓分支 PR 已是常态——前端树的合入就是 PR/分支流）。

### 8.1 安全与暴露（本轮最重要的新增）

- **S1 公共仓 + self-hosted runner 接 PR 事件**：主流安全清单的高危组合（不可信来源代码在持久化 runner 上执行；主流做法是 ephemeral 容器/一次性 VM，或 self-hosted 只收可信触发）。修法三选一：①slo-full 加事件门控（只跑 push/schedule；PR 的 slo-full 走合并后补验或手动 dispatch）——这是**隔离**关切、不是削弱验证，但触碰 ci.yml 冻结面与 mode-6「no skippable」文字 ⇒ **机主批**；②slo-full 挪独立机器/临时 runner；③仓转 private（连带解决 S2）。
- **S2 运维档案公开**：.scratch 占跟踪文件 89% 且全公开，其中 `injection-timeline.md` 是「对本项目 agent **实证有效**的 20 代攻击形状手册」、派单存档含机主原话与内部判据——对手读它比读代码值钱。主流：ops/安全笔记私密。三选项摆机主：a 转私有 / b .scratch 移出仓＋冷存 hash 索引（证据链可寻址性保留） / c 接受并记录在案。底线选项：injection-timeline 的「有效形状」细节脱敏。
- **S3 dev 无分支保护**：force push 未禁、required checks 未挂——「推送前看 CI／红即停」没有任何机械形态。主流默认配置一步到位：require lint+test-core+test-windows+slo-smoke＋禁 force push（编排者仍可管理员直推）。仓库设置一句话，**机主点头即装**。

### 8.2 并行模型

- **W1 每腿一 worktree（仓外）**：共享工作树是「面互斥／树呼吸／pathspec 纪律／锚点引 HEAD」四大补偿成本的总根源；README 规则 2 自己写过「>1 写码代理必须 worktree 隔离（third_party junction 复用）」，只被「⛔ 仓**内**建 worktree」挡住。落法：worktree 建 `D:\tmp\wisp\<日期>\<腿>\`（合规矩 10），third_party/models 用 junction；`cmd/wisp` 面互斥相应放宽为「同面同分支串行」。主流编排 harness 默认隔离；解锁写腿并发 2–3 → 4–6。
- **W2 编排者单点串行**：三把尺/翻框/-done 全过一手。机械半（提交在/件在/build+d22scan+长度门 rc）**脚本化**，编排者只裁判断半——审计 B6 那 ~10 张「全勾只差收尾」票当天清完。

### 8.3 路由与成本

- **R1 按腿型的模型路由策略成文**：机主 10-22 为换路由全停机（A1136/A1148）——路由是全局手动开关。主流：per-task routing。建议入编排者检查表：aN 普查→快模型；rN 落地→强模型；vN 终裁→强模型＋高推理档；mN 变异→中档。成文后「换路由」变查表、不再停机。
